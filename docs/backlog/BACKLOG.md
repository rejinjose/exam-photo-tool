### T-09: Resize to exact pixels
Status: todo | Owner: Claude | Depends on: T-08
Story: As a student, I want my photo at the exact pixel size the form requires.
Acceptance criteria:
- `resize()` in `src/lib/` outputs exactly the preset width × height.
- Large downscales use stepped resizing (or equivalent) to avoid jagged, blurry output.
Tests: output dimensions for several input sizes and ratios.

### T-10: Compress to KB range
Status: todo | Owner: Claude | Depends on: T-09
Story: As a student, I want my file inside the exam's KB limits so the form accepts it.
Acceptance criteria:
- `compressToRange()` binary-searches JPEG quality and returns `{ blob, sizeKB, quality }` within `minKB`–`maxKB`.
- Returns a structured failure (not a silent bad file) when: the file can't get under `maxKB` without dropping below a minimum quality floor, or can't reach `minKB` even at top quality.
- UI shows a plain message for each failure with a suggested fix.
- **Open decision for Rejin:** how to handle "can't reach minKB" — ask before choosing an approach.
Tests: hits range on fixtures for several rule sets; both failure cases.

### T-11: Process in a Web Worker
Status: todo | Owner: Claude | Depends on: T-10
Story: As a student on a cheap phone, I want the page to stay responsive while my photo processes.
Acceptance criteria:
- Resize + compress run in a Web Worker using OffscreenCanvas, with a main-thread fallback when unsupported.
- Loading state shown during processing; errors from the worker reach the UI.
Tests: worker and fallback paths produce the same output for a fixture.
